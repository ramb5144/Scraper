## Gap Resolution Details

### Gap 1: Code/Pre Exclusion Mismatch (Phase 2)

**Status:** ✅ RESOLVED

**Timeline:**
- **Identified:** Phase 2 (02-02), exclusion-logic-comparison.md
- **Root cause:** Quick-007 changed SDK to encrypt code blocks, decrypt-interceptor not updated
- **Fixed:** Quick-008 removed code/pre/kbd/samp/var from EXCLUDE_SELECTORS
- **File:** client/decrypt/src/position.js:217-218
- **Commit:** 4732671
- **Verified:** Phase 3 test "code and pre elements are encrypted" passes

**Impact before fix:**
```
Page: <p>Para 1</p><code>CODE</code><p>Para 2</p>
SDK plaintext: "Para 1\nCODE\nPara 2" (positions 0-6, 7-11, 12-18)
DI position map: "Para 1\nPara 2" (positions 0-6, 7-13)
Result: Server position 12 → DI thinks position 7 → wrong text copied
```

**Impact after fix:**
```
Both SDK and DI include code blocks in position calculations
Position mapping accurate
Copy/paste returns correct text
```

### Gap 2: Clipboard Copy Returning Empty/Encrypted (Phase 3)

**Status:** ✅ RESOLVED

**Timeline:**
- **Identified:** Phase 3 (03-02), 8 copy/paste tests getting encrypted text
- **Root cause:** Missing `e.clipboardData.clearData()` before `setData()`
- **Impact:** Browser copied BOTH encrypted and decrypted text
- **Fixed:** Quick-009 added clearData() call
- **File:** client/decrypt/src/copy.js:296-299
- **Commits:** f6b7375, 5baeff8
- **Verified:** All 11 copy/paste tests now passing

**Technical explanation:**
Without `clearData()`, browser's default copy behavior runs alongside custom handler, putting both encrypted (from selection) and decrypted (from handler) text on clipboard. In Playwright, this resulted in empty or encrypted reads.
