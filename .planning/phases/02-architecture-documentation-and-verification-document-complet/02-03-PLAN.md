2. **Symptom: Text appears as gibberish (encrypted characters visible)**

Decision Tree:
```
├─ Check 1: Is the text encrypted?
│  ├─ How to check: Open DevTools → Elements → find the text → is it scrambled letters?
│  │  Also check: node._cloakEncrypted property
│  ├─ YES (encrypted) → Check 2
│  └─ NO (plaintext) → Root cause: SDK didn't encrypt this text
│     └─ Fix: Check if element is in excludeSelectors, verify SDK init completed
│
├─ Check 2: Are encrypted fonts loaded?
│  ├─ How to check: DevTools → Network → filter "woff2" → are fonts 200 OK?
│  ├─ YES → Check 3
│  └─ NO → Root cause: Font loading failed
│     └─ Fix: Check CORS headers, R2 storage, font URL validity
│
├─ Check 3: Are encrypted fonts APPLIED to this element?
│  ├─ How to check: DevTools → Elements → select element → Computed → font-family
│  │  Should show encrypted font name (e.g., "Arimo" from encrypted mapping)
│  ├─ YES (encrypted font applied) → Check 4
│  └─ NO (system font shown) → Root cause: Font application skipped
│     └─ Diagnose further:
│        ├─ Is element in data-cloak-exclude? → Font intentionally not applied
│        ├─ Does element have !important font-family? → CSS override issue
│        ├─ Is element dynamically added after init? → MutationObserver issue
│        └─ Check STEP 3.5 in cloak-sdk.js (lines 1416-1463)
│
└─ Check 4: Is there a CSS text-transform on this element?
   ├─ How to check: Computed styles → text-transform
   ├─ NO → Investigate font glyph mapping
   └─ YES → Root cause: text-transform mismatch
      └─ Fix: Check if SDK reset text-transform (line 371 in cloak-sdk.js)
```

  <action>
Create position-mismatch-guide.md for diagnosing copy/paste and search position issues.

Structure:
1. **Overview** - When to use this guide:
   - Copy/paste returns wrong text (offset from selection)
   - Search highlights appear in wrong location
   - Search finds matches but highlights wrong elements

2. **Symptom: Copy/paste returns wrong text**

Decision Tree:
```
├─ Check 1: Is position map built correctly?
│  ├─ How to check: Run window.debugPositionMapping() in console
│  │  Compare: "Decrypt-interceptor encrypted text length" vs "Server plaintext length"
│  ├─ Lengths match → Check 2
│  └─ Lengths differ → Root cause: Position map mismatch
│     └─ Diagnose:
│        ├─ Check block count: "Server has X blocks, interceptor has Y blocks"
│        ├─ Find diverging block: Compare block-by-block lengths
│        └─ Common causes: Block boundary mismatch, extra/missing newlines
│
├─ Check 2: Is selection position calculated correctly?
│  ├─ How to check: Select text → console.log getSelectionPositions()
│  │  Verify start/end match expected character indices
│  ├─ Positions correct → Check 3
│  └─ Positions wrong → Root cause: Selection calculation issue
│     └─ Check: getContainingBlockSkippingHighlights() for highlight interference
│
└─ Check 3: Is server returning correct text for positions?
   ├─ How to check: Call /api/search/get-text-range manually with positions
   ├─ Text correct → Bug elsewhere (clipboard API?)
   └─ Text wrong → Root cause: Server-side plaintext index mismatch
      └─ Check: R2 stored plaintext vs expected
```

3. **Symptom: Search highlights wrong location**

Decision Tree:
```
├─ Check 1: Are server match positions correct?
│  ├─ How to check: Call /api/search/find-matches, log positions
│  │  Manually verify positions in server plaintext
│  ├─ Positions correct → Check 2
│  └─ Positions wrong → Root cause: Server search issue
│
├─ Check 2: Is mapPositionsToDOMNodes mapping correctly?
│  ├─ How to check: Log domMatches from mapPositionsToDOMNodes()
│  │  Verify nodeRelativeStart/End match text boundaries
│  ├─ Mapping correct → Check 3
│  └─ Mapping wrong → Root cause: Position map doesn't match server
│
└─ Check 3: Are highlights being applied to correct nodes?
   ├─ How to check: Inspect <mark class="encrypted-search-highlight"> elements
   ├─ Correct nodes → Visual/styling issue
   └─ Wrong nodes → Root cause: DOM changed after position map built
      └─ Fix: Rebuild position map before highlighting
```

4. **Using debugPositionMapping()** section:
   - Full output explanation
   - How to interpret block-by-block comparison
   - Common divergence patterns and what they mean

5. **Known Position Issues** from verification:
   Read findings from verification/position-mapping-comparison.md created in plan 02-02.
   If 02-02-SUMMARY.md exists, reference its summary section as well.

| Issue | Symptom | Cause | Fix |
|-------|---------|-------|-----|
| Text-transform mismatch | Positions off on uppercase text | SDK uses transformed length, DI uses raw | Apply same transform in DI |
| Extra exclusions in DI | DI has fewer chars than server | DI excludes code/pre/etc that server included | Sync EXCLUDE_SELECTORS |
| Search highlight splits nodes | Positions wrong after search | <mark> creates new text nodes | Use shouldExcludeTextNodeForPositionCalc |

6. **Prevention Checklist**:
   - [ ] Verify BLOCK_ELEMENTS arrays match
